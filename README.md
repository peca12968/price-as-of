# Price As Of｜重建下單當時查得到的價格

4 月 13 日下單時，系統記載套件單價為 8.50 美元。4 月 20 日，商品團隊將特價生效日從 10 日更正為 14 日。此時回查同一筆訂單，適用單價變成 10.00 美元。這個 DuckDB 工具同時保留下單當時與指定查核日的答案，並列出各自採用的價格版本。

## 跑一次歷史查核

使用 Python 3.12 或 3.13，從專案根目錄執行。

```sh
python -m pip install -r requirements.txt
python audit.py examples/revisions.csv examples/orders.csv --as-of 2026-04-23T00:00:00Z
python -m unittest -v
```

3 筆可比較訂單的數量加權差額為 **+450 美分**。K13 由特價回到原價，K16 則因快閃特價被撤回而改採修正後的春季價。其餘 3 筆列入 `excluded_orders`，各自保留兩個時間點的狀態。此報告只重建價目表；實際收款、折扣碼及退款須有另外的交易資料。[價格修訂](examples/revisions.csv) · [訂單](examples/orders.csv)

## 兩個時間怎麼進入查詢

1. 每次價格修訂記錄業務生效時間 `effective_at` 與系統登錄時間 `recorded_at`。SQL 先用 `lead(recorded_at)` 求出同一筆價格變更的下一次登錄時間，每版從登錄時刻起可見，到下一版登錄時結束。這一步保留撤回版本，才能正確結束舊版本。
2. 每筆訂單提出兩次查詢。業務時間皆為下單時刻，可用資料的截止時間分別為下單時刻及 `--as-of`。從當時可見的版本中，找出訂單成立前或同時已生效的價格。
3. 以 `dense_rank` 找出最近生效的所有候選。只有一個候選時輸出 `priced`，完全缺少則輸出 `missing`。多筆變更同時生效會輸出 `ambiguous`，即使候選金額相同也保留所有來源。每個來源附變更 ID、版本、生效時間、登錄時間及單價。[查詢原始碼](prices.sql) · [DuckDB 視窗函式](https://duckdb.org/docs/2.0/sql/functions/window_functions)

## 輸入與重跑

- 兩份 CSV 的表頭及欄位順序見範例。每個訂單 ID 對應一筆訂單明細，數量須為正整數。所有價格採單一幣別，以非負整數美分表示；零元是有效價格。兩份檔案均可只含表頭。
- 同一 `change_id` 從第 1 版 `set` 開始，版本連續、SKU 固定、登錄時間嚴格遞增。後續 `set` 可以更正金額或生效日。`withdraw` 的生效時間與金額留白，撤回後會重新尋找當時可用的其他價格。
- 接受含 `Z` 或時區偏移的時間，支援至微秒，內部統一換算成 UTC。查核截止時間須涵蓋輸入的所有訂單。修訂可亂序或重送；相同版本若內容相異會回報錯誤。報告寫到標準輸出，無法驗證的輸入會以結束碼 2 結束。
- 每次執行將輸入載入記憶體中的 DuckDB。適用單機批次歷史回查，執行所需資源依修訂數、訂單數及每個 SKU 的候選價格數而變動。

## 如何驗證

### 匯出可查詢的稽核明細

```sh
python audit.py examples/revisions.csv examples/orders.csv --as-of 2026-04-23T00:00:00Z --parquet april.parquet
```

每筆訂單輸出一列，包含查核截止時間、兩次單價與狀態、兩組巢狀來源明細及數量加權差額。時間統一為 UTC；來源明細的生效及登錄欄位使用 UTC 的無時區時間戳。無法比較的差額保持 NULL，零元差額保留為零。金額差採 DECIMAL(38,0)，即使單價與數量都到達輸入上限也能精確保存。提供新的目的檔名即可匯出，程式在同一目錄暫存完整結果，再透過硬連結發布，既有目的檔會得到結束碼 2。

檔案依回查單價、訂單編號排序，以便下游依價格範圍查核。跨專案演練交錯建立 6,144 筆訂單，尋找單價 800 美分且數量為 2 的訂單。Rowgroup Scout 從檔尾識別出三組中只有一組需要保留，再以 DuckDB 實查並逐筆核對全部 1,024 個訂單編號。[整合演練](layout_drill.py) · [Rowgroup Scout](https://github.com/peca12968/price-as-of/tree/main/modules/rowgroup-scout)

### 核對雙時間查詢

測試以固定種子建立 180 筆價格修訂與 240 筆訂單，在 3 個查核截止時間逐筆比對兩種觀點，共 1,440 次價格查詢。獨立 Python 實作按登錄順序逐筆套用修訂與撤回，再搜尋當時有效的候選，核對狀態、價格、來源版本及時間。邊界測試另外涵蓋修訂前一微秒、修訂當下、零元價格、相同金額的歧義及亂序重送。[測試程式](test_audit.py)

**履歷用語**　以 DuckDB 視窗函式實作雙時間價格查核，支援補登、更正、撤回及同時生效的價格衝突；用 Python 重播歷史版本，逐筆核對 1,440 次查詢結果。

本專案使用 AI 輔助開發。商品、價格與訂單皆為合成資料。
