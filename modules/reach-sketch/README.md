# Reach Sketch｜兩個站點共有多少位訪客？

網站有 20,000 位訪客，App 有 18,000 位，其中 8,000 位用過兩邊。兩站各自在本機將訪客 ID 算成一份 HyperLogLog 摘要，總部只需要合併摘要，就能估算跨站去重人數。此例估出 **29,795 位**，比實際的 30,000 位少 205 位（−0.683%）。

## 重現跨站統計

在專案根目錄以 Go 1.25 以上與 Python 3.12 以上執行。工具本身僅使用 Go 標準函式庫。

```sh
python demo.py
go test -v ./...
```

示範從兩組合成 ID 產生輸入，每站另外重送 500 筆。網站採用精度 14，App 採用精度 12。合併後採用精度 12，4,096 個暫存器加上標頭和校驗碼共 4,105 位元組。示範程式會用 Python 的集合求出真實人數，再以另一套位元字串實作核對每個暫存器、二進位格式與估算值。[可執行示範](demo.py)

自己的輸入檔每行一個 UTF-8 ID，支援 LF 與 CRLF。每個 ID 限 1 至 4,096 位元組，空白字元屬於 ID 的一部分。兩站需使用同一套 ID，大小寫與 Unicode 正規化方式也應一致。

```sh
go run . build 14 web.txt web.rch
go run . build 12 app.txt app.rch
go run . merge both.rch web.rch app.rch
go run . report both.rch
```

`build` 的輸入路徑可填 `-` 從標準輸入讀取。`merge` 可依任意順序傳入多份摘要，同一份可重複出現。`report` 輸出 JSON，包含估計人數、精度、暫存器數及典型相對標準誤。輸出路徑須為新檔名，工具在同目錄寫完暫存檔後以硬連結發布，適用支援硬連結的本機檔案系統。無法辨識的格式、校驗碼錯誤、非法等級或截斷檔案均會回報錯誤。

## 估算與合併

工具取 SHA-256 的前 64 位元。前 `p` 位元指定暫存器，剩餘位元的前導零個數決定等級。每格只保留見過的最大等級，因此重送相同 ID 不影響狀態。查詢以調和平均估算基數，小樣本使用空暫存器比例修正。精度可選 4 至 18，記憶體中的暫存器陣列大小為 2 的 `p` 次方個位元組。檔案記錄摘要，無法逐一列出訪客或扣除某筆特定訪問。

同精度摘要可逐格取最大值。兩份精度不同時，較細的索引需要摺疊到較粗的格子。例如從 14 降到 12，原索引末兩位會變成計算等級時的頭兩位。末兩位為 `00` 時原等級加二，為 `01` 時等級是二，為 `10` 或 `11` 時等級是一。空格略過。如此得到的每一格與直接用低精度讀取原始 ID 相同。

在均勻雜湊假設下，HyperLogLog 的典型相對標準誤約為 `1.04 / √m`，其中 `m` 是暫存器數。這是分布統計量，單一批次的誤差可能更大。此實作針對一般分析用途，沒有接近 64 位元雜湊空間飽和時的大基數修正。[HyperLogLog 原始論文](https://dmtcs.episciences.org/articles/3545)

## 測試如何區分合併錯誤與估算誤差

- **合併正確性**　對支援範圍內全部 120 種來源與目標精度配對，逐格比較摺疊後的摘要與直接用目標精度讀取的摘要。測試涵蓋空格、全零雜湊及長前導零。
- **估算誤差**　固定種子產生 48 組各有 20,000 個不同 ID 的合成樣本。在精度 10 下，相對誤差的均方根為 3.125%。這與開頭精度 12 的單一跨站範例分開計算。
- **資料交換**　示範用三種方式建檔，分別為跨精度合併、交換順序且重送，以及讀取全集一次。三份結果逐位元組相同。[Go 測試](sketch_test.go) · [跨程序示範](demo.py)

**履歷用語**　以 Go 實作可合併的 HyperLogLog 訪客統計工具，用跨語言參考實作核對分站合併結果，並以已知基數的合成資料量測估算誤差。
