# Cohort Replay｜重建當時看得到的週留存

11 月 16 日看報表，11 月 2 日那週註冊的兩個人，次週回訪人數是零。隔天系統補收到一筆發生於 13 日的活動。用同一個觀察窗口再算一次，留存就從 0/2 變成 1/2。這個 Python 與 SQLite 工具可以重建兩版報表，列出被補登資料改寫的格子。

## 跑一次範例

使用 Python 3.12 與 SQLite 3.38 以上。從專案目錄執行，僅需 Python 標準函式庫。

```sh
python cohort.py import demo.sqlite examples/events.jsonl
python cohort.py report demo.sqlite --through 2026-11-16T00:00:00Z --as-of 2026-11-16T00:00:00Z --last-week 2
python cohort.py diff demo.sqlite --through 2026-11-16T00:00:00Z --before 2026-11-16T00:00:00Z --after 2026-11-18T00:00:00Z --last-week 2
```

| 11 月 2 日註冊群組 | 16 日當時已知 | 18 日回查同一窗口 |
| --- | --- | --- |
| 註冊當週 | 1/2 | 1/2 |
| 次週 | 0/2 | 1/2 |
| 第 2 週 | 尚未觀察完 | 尚未觀察完 |

`diff` 輸出一格變動，含兩版的成員數、活躍人數與留存比例。如果後來補到更早的註冊紀錄，同一個人可能改歸另一個註冊週。整個群組新增或消失時，對應版本的格子為 `null`。兩版比較使用同一個 SQLite 讀取快照。

## 報表怎麼計數

- `--through` 是活動觀察截止，`--as-of` 是可用資料的截止，兩者都不含指定瞬間。`--as-of` 須涵蓋觀察截止。來源系統提供事件的 `occurred_at` 與 `recorded_at`，因此同一份已匯入的歷史資料即可重播。
- 以當時可見的首筆註冊決定群組。每週從 UTC 週一零時開始，第 0 週是註冊所在的日曆週。只有註冊當下或之後發生的 `active` 才計入分子，同一人在同一週的多次活動只算一次。
- 完整週即使沒有活動，也會列出 0。觀察截止時尚未結束的週，其人數 `active` 與比例 `retention` 都是 `null`。分母 `members` 仍列出截至查詢時已知的成員數。`--last-week` 控制最後列出的週次，範圍為 0 至 104。
- 事件採 JSON Lines，時間需含秒和明確時區。同一識別碼重送且內容一致會略過，等價的時區寫法也會視為同一瞬間。同鍵內容衝突或資料列無效時，整批新增會回滾。這個版本處理不可變的註冊及活動事件，已知時間取決於來源登錄紀錄的完整性。[範例資料](examples/events.jsonl) · [SQL 查詢](retention.sql)
